# Rebuild from the irreducible constraints

```
Reduce this problem to its irreducible constraints and rebuild it from zero.
```

Status: candidate. It moves into the list when 3 people, other than the author, post a public receipt.

## Where it came from

Wyrmfalls [posted it on X](https://x.com/Wyrmfalls/status/2118826627408830479) on Nov 6, 2026, in a list of five prompts, as a reply to [Bootoshi's call](https://x.com/KingBootoshi/status/2118803776387928228) for god tier prompts.

## What it means

A constraint is something the solution must satisfy: a data size, a deadline, a business rule, an API you cannot change. "Irreducible" keeps only the constraints you cannot remove. Much of what a design assumes is habit, not a real constraint. "Rebuild it from zero" asks for a new design that rests on those constraints only, instead of one more patch on the old design.

Use it on code or a plan that grew patch by patch. Compare the rebuild with what you have. You do not have to adopt it; the list of real constraints is useful by itself.
